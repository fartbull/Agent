# Documentation Template

A template for writing documentation.

```markdown
# {Title}

> {One-sentence summary}

## Overview

{Brief overview of what this covers, why it matters, and who should read it.}

## Prerequisites

{What the reader needs before following this guide.}

## {Section 1}

## {Section 2}

## Examples

```bash
{or yaml, or json — always specify language}
```

## Troubleshooting

| Problem | Solution |
|---------|----------|
| {problem} | {solution} |

## See Also

- [Link title](../../path/to/doc.md)
- [Link title](../../path/to/doc.md)
```

## Writing Guidelines

- **Be concise** — lead with the conclusion
- **Be technical** — use exact paths, commands, API names
- **Be specific** — "Use `pip install`" not "Install the package"
- **Use TODOs** — `TODO: Verify` for unverified claims
- **Link, don't duplicate** — reference other docs instead of copying
- **Test all commands** — if you can't test it, mark it as needing verification
